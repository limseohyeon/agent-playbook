# 작업 일지 작성

완료한 개발 또는 작업의 배경, 의사결정, 구현, 검증, 회고를 읽기 쉬운 한국어 Markdown 일지로 정리한다.

## 호출 조건

- 사용자가 `$write-work-log`를 직접 호출한 경우 실행한다.
- 사용자가 "개발일지 작성해줘", "작업 일지로 정리해줘"처럼 일지 작성을 명시적으로 요청한 경우 실행한다.
- 일반적인 개발 요청, 단순 요약 요청, 작업 완료만으로는 실행하지 않는다.

## 작성 절차

1. [assets/work-log-template.md](../../../../../skills/global/write-work-log/assets/work-log-template.md)를 처음부터 끝까지 읽는다.
2. 현재 대화, 사용자가 제공한 정보, 이미 확인된 작업 결과에서 사실을 수집한다.
3. 문제, 목표와 제약, 대안, 해결 방법, 구현, 검증, 회고, 후속 과제로 정보를 분류한다.
4. 템플릿의 구조를 유지하면서 안내 문구와 예시를 실제 내용으로 교체한다.
5. 중복되거나 해당하지 않는 하위 항목과 표의 빈 행은 제거한다. 주요 섹션에 필요한 정보가 확인되지 않으면 추측하지 말고 `확인되지 않음`으로 표시한다.
6. 완성된 일지를 채팅 본문에 Markdown으로 바로 출력한다.

## 작성 원칙

- 기본 언어는 한국어다. 사용자가 다른 언어를 요청하면 그 언어를 따른다.
- 제목, 한 줄 요약, 핵심 결과만 읽어도 작업의 목적과 성과를 이해할 수 있게 쓴다.
- 확인된 사실만 단정한다. 원인이 가설이라면 가설임을 표시한다.
- 커밋, PR, 이슈, 문서, 테스트 결과는 실제로 확인된 값만 기재한다.
- 대안이 실제로 검토된 경우에만 대안 표를 채운다. 검토하지 않은 대안을 사후에 만들어내지 않는다.
- 개선 전후를 뒷받침할 정보가 있을 때만 비교표에 구체적인 차이를 쓴다.
- 동작 흐름이 의미 있을 때만 흐름도를 유지하고, 실제 실행 순서로 바꾼다.
- 상투적인 설명, 같은 내용의 반복, 불필요한 장황함을 피한다.

## 출력 제한

- 일지 파일을 생성하거나 수정하거나 저장하지 않는다.
- 외부 문서, 이슈 트래커, 메모 서비스에 기록하지 않는다.
- 결과 전체를 코드 블록으로 감싸지 않는다. 사용자가 원문 복사용 Markdown을 요청한 경우에만 코드 블록을 사용한다.
- 정확한 일지를 작성하는 데 반드시 필요한 핵심 정보가 없을 때만 한 번에 모아 짧게 질문한다.
